# MARKOVLAB 9.5+ — шлифовочный production-промт

Работай не как консультант и не как генератор рекомендаций. Ты одновременно Principal Product Designer, Staff Frontend Engineer, UX Researcher, Art Director, Evidence UX Editor, Accessibility Engineer и QA Lead.

Твоя задача — фактически доработать существующий MARKOVLAB до честного production-уровня не ниже 9.5/10. Изменяй код, контент, изображения, темы, тесты, документацию и GitHub. Не присылай план вместо результата и не останавливайся после первого работающего варианта.

## Исходная проблема

Текущая версия функциональна, но воспринимается примерно как 6/10:

- текст, подписи и границы слишком бледные;
- мелкая типографика делает интерфейс трудночитаемым;
- большие пустые области не создают премиальную композицию;
- лаборатории выглядят как технический реестр;
- изображения показывают абстрактный бренд, но слабо объясняют применение;
- пользователь получает число, но не всегда понимает, где оно меняет решение;
- автор MARKOVLAB почти не присутствует в продукте;
- System визуально повторяет Light или Dark без объяснения;
- нет полноценного режима анализа для продвинутого пользователя.

## Главный результат

MARKOVLAB должен ощущаться как авторский precision instrument, который соединяет:

**вопрос → измерение → результат → смысл → ограничение → сценарий → решение → действие → повторная проверка.**

Красота не компенсирует слабую читаемость. Количество функций не компенсирует непонятное применение. Pro-режим не должен создавать ложную точность.

## 1. Читаемость — абсолютный P0

Проверь все основные поверхности в Light, Paper, Dark и Midnight.

- Основной текст и интерактивные подписи должны соответствовать WCAG 2.2 AA.
- Не используй 8–10 px для содержательного текста.
- Увеличь secondary text, labels, metadata, result explanations и laboratory descriptions.
- Усиль контраст borders, placeholders, muted text и chart labels.
- Проверь русский текст на 320, 390, 768, 1366 и 1920 px.
- При 200% zoom смысл и действия должны сохраняться.
- Не решай читаемость жирностью всего интерфейса: используй размер, контраст, длину строки и иерархию.

## 2. Осмысленная фотография

Добавь cohesive editorial photo layer. Каждая фотография обязана показывать реальный момент применения:

- измерение тела;
- планирование питания;
- разбор тренировки и восстановления;
- сравнение сценариев и принятие решения.

Стиль: premium documentary editorial photography, natural daylight, mineral/ivory/graphite/deep-forest palette, tactile real materials, restrained composition.

Запрещено: stock smiles, случайные фитнес-модели, врачебные клише, neon, fake UI, нечитаемый AI-текст, watermark, бренды, пластиковая ретушь.

Фотография должна находиться рядом с соответствующим сценарием и иметь смысловой caption. Оптимизируй в WebP, укажи width/height, object-fit, loading и корректный alt. Декоративные изображения получают `alt=""`.

## 3. Практическое применение

Для каждой из девяти лабораторий добавь практический блок:

1. Где возникает задача.
2. Какие данные зафиксировать.
3. Как прочитать результат.
4. Какое решение он способен изменить.
5. Когда повторить измерение.
6. Главное ограничение.

Не используй общий текст для всех направлений. Body, Energy, Nutrition, Strength, Cardio, Recovery, Mind, Money и Utility должны иметь разные реальные контексты.

На странице каждого калькулятора явно показывай «Где применить». Формулировка должна отвечать на вопрос пользователя, а не пересказывать название формулы.

## 4. Авторский слой

Добавь прямую речь автора Павла Маркова на Home и About.

Тон: спокойный, требовательный к точности, практичный, без самовосхваления и маркетингового пафоса.

Основная позиция:

> MARKOVLAB создан не ради коллекции формул. Число становится ценным только тогда, когда помогает понять ограничение, изменить решение и проверить результат повторно.

Не придумывай биографию, награды, отзывы или медицинские полномочия. Подпись: «Павел Марков · автор MARKOVLAB» / “Pavel Markov · creator of MARKOVLAB”.

## 5. Темы без визуального дублирования

Сохрани System как поведение, а не отдельную палитру. Сделай четыре реально разные палитры:

- Light — чистая mineral light;
- Paper — тёплая editorial paper;
- Dark — глубокая forest/graphite;
- Midnight — холодная blue-graphite night.

System следует настройке ОС и прямо объясняет, какая тема будет применена. Добавь preview swatches. Проверь сохранение, раннее применение без FOUC и реакцию на изменение системной темы.

## 6. Pro-режим для 86/86 калькуляторов

Каждая calculator page получает переключатель Basic / Pro.

Basic:

- быстрый расчёт;
- все обязательные данные;
- основной результат, смысл и действие.

Pro:

- полный протокол каждого входа;
- технические допущения;
- sensitivity driver;
- сравнение Scenario A и Scenario B;
- изменение выбранного входа на −10%, −5%, +5% и +10%;
- delta результата, когда она математически определима;
- evidence class и главное ограничение.

Pro использует ту же проверенную формулу. Он не добавляет произвольные коэффициенты, magical score или фиктивную уверенность. Если у метода нет научно обоснованного дополнительного параметра, прямо скажи об этом.

Проверь Pro-режим автоматически для всех 86 calculator IDs.

## 7. Visual composition

- Не превращай всё в cards.
- Создай чередование editorial photography, data surfaces, lists и authored notes.
- Удали пустоту, которая не создаёт фокус.
- Используй сильную, но сдержанную типографическую шкалу.
- Laboratory atlas должен иметь изображение, вопрос, количество инструментов и ясный hover/focus state.
- Mobile не должен быть уменьшенной desktop-версией.

## 8. Безопасность и доказательность

- Не меняй формулы без отдельной проверяемой причины.
- Не выдавай оценку за измерение.
- Не добавляй диагнозы или медицинские обещания.
- Не выдумывай точность.
- Сценарий показывает чувствительность, а не прогноз будущего.
- User input и imported data экранируются и валидируются.

## 9. QA

Добавь и запусти тесты:

- 86/86 страниц имеют Pro surface;
- все generated/editorial assets существуют;
- RU/EN присутствуют во всех новых блоках;
- Paper является валидной темой;
- неизвестная тема безопасно мигрирует в System;
- PWA cache включает новые assets;
- runtime version согласована;
- нет remote runtime dependencies;
- нет TODO, FIXME, placeholder, lorem, NaN или undefined;
- Home, Category, Calculator Basic, Calculator Pro и About проходят render test.

Сделай browser QA минимум в Chromium:

- 320×568;
- 390×844;
- 768×1024;
- 1366×768;
- 1440×900;
- Light / Paper / Dark / Midnight;
- RU / EN;
- Basic / Pro;
- Scenario A/B;
- keyboard navigation;
- console/network errors;
- offline reload.

3. Работай в `work/markovlab-9-5-polish`.
4. Сделай осмысленные commits.
5. Создай PR.
6. Проверь diff и CI.
7. Исправь проблемы.
8. Merge в `main`, если permissions позволяют.
9. Проверь живой GitHub Pages deployment.

## Definition of done

Работа не завершена, пока:

- сайт читается без усилия;
- четыре палитры действительно различаются;
- System понятно объяснён;
- фотографии связаны с реальными действиями;
- у всех девяти лабораторий есть практический контекст;
- авторский голос присутствует, но не доминирует;
- Pro работает на 86/86 страницах;
- сценарный анализ меняет входные данные и честно сравнивает результат;
- RU и EN не смешиваются;
- mobile, tablet и desktop выглядят законченными;
- тесты green;
- production проверен после merge.

Не ставь 9.5 автоматически. Сначала оцени каждую P0-область по screenshots и пользовательским сценариям. Если читаемость, calculator UX, practical value, themes или mobile ниже 9/10 — продолжай дорабатывать.
